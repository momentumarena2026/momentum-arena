PhonePe **Dynamic QR (DQR)** is the UPI-first checkout path that replaces the static-QR + manual-UTR flow (`lib/phonepe-dqr.ts`, routes under `app/api/phonepe/dqr/*` + `dqr-callback`). It's the dynamic sibling of the legacy static-QR product and uses the same **V1 X-VERIFY** scheme (NOT the OAuth v2 checkout in `lib/phonepe.ts`).

**THE GOTCHA (cost hours):** prod creds sent to the **UAT host** return `HTTP 500 INTERNAL_SERVER_ERROR` / "There is an error trying to process your transaction at the moment. Please try again in a while." — looks like a transient PhonePe blip but actually means `PHONEPE_DQR_ENV` wasn't applied at runtime → request went to UAT. Root cause was **Vercel env scope**: the var must be set on the environment that serves the branch (the `development` branch deploys as a **Preview**, so the var must be on the Preview scope, alongside the `PHONEPE_DQR_*` creds), and **env changes require a redeploy** to take effect. Verified failure-mode mapping against prod: bad checksum/salt/whitespace/quotes → `401 UNAUTHORIZED`; wrong salt **index** → `500 KEY_VAULT_EXCEPTION`; prod creds on UAT host → `500 INTERNAL_SERVER_ERROR`.

**Request shape (confirmed against PhonePe docs + live prod):** body = `{ "request": "<base64(payload)>" }`; `X-VERIFY = SHA256(base64 + "/v3/qr/init" + saltKey) + "###" + saltIndex` signing the **logical** path (never the `/enterprise-sandbox`-prefixed UAT URL); callback passed as the **`X-CALLBACK-URL` header** (no PhonePe dashboard registration), derived from the request's own host (`x-forwarded-host`) so dev→dev and prod→prod. `terminalId` optional. amount in paise. Creds for SPORTIVEVENTURES live in `PHONEPE_DQR_*` env vars. Related: [[project_booking_system]].
