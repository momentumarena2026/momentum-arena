**⚠️ GOTCHA: `require()`'d image assets render BLANK over OTA (2026-07-07).** On this self-hosted Expo Updates setup, a new/changed `require("...x.png")` image does NOT display on an app whose native binary was built before that asset existed — even though `expo export` bundles it, `scripts/publish-ota.ts` uploads it to Blob, and the manifest correctly lists it (verified: 38 image/png assets served). The device just renders a blank tile. This hit the UPI payment sheet: every UPI logo AND the Momentum header logo were blank on the OTA'd build. **Fix pattern: inline images as base64 data URIs in the JS bundle** (which OTA always ships in full) instead of `require()`. See `apps/mobile/src/components/payment/upi-icons.generated.ts` + generator `scripts/gen-upi-icons.py` (`<Image source={{ uri: dataUri }}>`). ~166KB for 22 icons was fine. Root cause not fully diagnosed (likely embedded-asset resolution vs OTA-downloaded-asset mapping) — a new NATIVE build would also embed+fix them, but base64 works today without one. **Rule: any NEW image an OTA-only change needs must be base64-inlined, not require()'d.** Also reconfirmed the other half of "why didn't my change show": development-channel OTA publishes a **DRAFT** — it must be rolled out from /admin/ota (I now do this as part of shipping mobile changes; a stuck draft = stale JS on device).

**Version gate: uploaded ≠ downloadable (fixed 2026-08-02, main 9fc0c39).** `AppVersionGate.latestBuild` was written by CI the instant a binary was *uploaded* (post-native-release → `set-version-gate.ts`), but the app reads it as *available* (`updateAvailable = installed < latestBuild`), so customers got an "Update available" nag deep-linking to a store page still serving the old version — App Store review is hours-to-days, and our Play uploads land as `release_status: "draft"`. Now:
- `AppVersionGate.latestIsLive` + `liveConfirmedAt`. CI writes production builds with `latestIsLive=false`; **development** (TestFlight / Play internal) stays live-on-upload since testers get those in minutes.
- `/api/app/version-check` ANDs on `latestIsLive` — **server-side, so it fixes every already-installed build with no app release**.
- `lib/store-availability.ts` + `scripts/check-store-availability.ts`, hourly via `.github/workflows/cron-store-availability.yml` (`20 * * * *`): **iOS = public iTunes Lookup** (`itunes.apple.com/lookup?bundleId=com.momentumarena&country=in` → live marketing version, no creds); **Android = Play Developer API** `edits.tracks.get(production)` via `GOOGLE_PLAY_JSON_KEY` (JWT→OAuth by hand with `jsonwebtoken`; only `status:"completed"` at 100% counts). Runs as an **Actions job, not the usual `/api/cron/*` ping**, because the Play key lives in Actions secrets. Lookups fail soft and only flip false→true — an outage can never silence a real prompt.
