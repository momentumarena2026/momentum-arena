Full manual-deploy runbook lives in-repo at **docs/DEPLOYMENT.md**; the production launch-readiness checklist (what's left to go live) is **docs/GO-LIVE.md** (main e9fd399). Key facts:

**⚠️ PENDING NATIVE CHANGE (2026-06-30, main bfedd8b):** the mobile app added **expo-file-system + expo-sharing** (config plugin) for the admin "Reports → Download & share" feature (download to cache → OS open-with/share sheet; new bearer route app/api/mobile/admin/reports/[id]/download). This is the FIRST native change after a long OTA-only streak → the app **fingerprint changed**, so report download/share (and everything since) only reaches users in a NEW STORE BUILD, not via OTA. Dev push auto-dispatches the test build (ota-publish self-heal); **production needs a manual native build** — i.e., the launch build (`gh workflow run native-ios.yml --ref main -f track=appstore` + native-android `-f track=production`) MUST be cut, after which post-native-release commits the prod fingerprint baseline and OTA resumes. All other mobile work this session was JS-only/OTA-shippable; this one gates on the build.

**Go-live status (2026-06-29):** web LIVE; iOS on TestFlight (build 29706516 rtv2), Android on Play Internal (versionCode 29706573 rtv2) — NEITHER on production store tracks yet. Prod OTA channel dormant until the first prod native build commits a prod fingerprint baseline (auto via post-native-release). Blockers to public launch (all user/vendor): Razorpay LIVE keys + RAZORPAY_WEBHOOK_SECRET (now documented in .env.example; without it orphan-recovery webhook silently never fires); PHONEPE_ENV=PRODUCTION + prod creds + webhook user/pass; MSG91 prod keys; `gh workflow run native-ios.yml --ref main -f track=appstore` + native-android `-f track=production` then submit in store consoles; reviewer OTP bypass (<APPSTORE_TEST_PHONE>/<APPSTORE_TEST_OTP>) must be set during review then REMOVED from prod after approval; rotate chat-leaked STAGING_DB_URL+BLOB_READ_WRITE_TOKEN; activate APPFIRST. **Deploy scripts need NO edits for prod** — pipeline is env/branch-aware; prod is driven by Vercel Production-scope env values + the `track=appstore|production` dispatch input. DQR optional/dormant (UPI falls back to static QR).

- **Branches:** `development` → staging, `main` → production. Only these two deploy (Vercel allowlist in scripts/vercel-ignore.sh; also skips web build when the diff is entirely under apps/mobile/). Vercel git-integration auto-deploys on push; build = `next build` (no DB touch).
- **Schema sync = `prisma db push --accept-data-loss`** (NOT migrate deploy), now TWO AUTOMATIC LAYERS (development `abb3170`, 2026-07-02; verified live same day — deploy success + path filters confirmed):
  1. **Inside every Vercel build** — `scripts/vercel-build.sh` (the package.json `build` script): cleanup SQL → db push → next build. Deploys are SCHEMA-ATOMIC (code can't go live before its columns exist; failed push = failed build = previous deployment keeps serving). Preview→staging DB, Production→prod DB via each scope's DATABASE_URL. Local `npm run build` skips DB steps ($VERCEL guard).
  2. **seed-staging.yml / seed-production.yml** — now PATH-FILTERED to `prisma/**` + `workflow_dispatch` recovery hatch; they own seeding (seed.ts superadmin upsert) + belt-and-suspenders db push.
- **THE `[skip ci]` CONVENTION IS RETIRED** — promotions are plain merges, NO token decision ever. Do not write skip tokens in commit messages at all (path filters make them unnecessary). The one legit remaining use: machine-generated fingerprint auto-commits by workflows (prevent ota-publish retrigger loops).
- **⚠️ FOOTGUN that forced the redesign (2026-07-02, commit 48a0629):** GitHub matches skip tokens ANYWHERE in the commit message — a body sentence "NO [skip ci]: seed must run" skipped the workflow → staging P2022 crash + stale OTA draft. A pre-push hook (machine-local, .git/hooks/pre-push, alongside the branch-allowlist policy) now blocks tokens in commit BODIES and tokens on schema/mobile pushes. Recovery if schema drift ever recurs: redeploy from Vercel (build re-runs db push), or dispatch the seed workflow, or local `npx prisma db push` with DATABASE_URL from repo-root .env.
- **dev→main promotion** (what the verifier runs): merge `origin/development` into a clean `origin/main`, gate-check `git diff origin/development HEAD` is EMPTY, then push HEAD:main. (I use a temp detached worktree; user can do it on a main checkout.)
- **Coupon/data seeds:** dedicated `workflow_dispatch` one-shots (seed-pickleball-coupon.yml, seed-app-first-booking-coupon.yml) — `gh workflow run <wf>.yml -f environment=production`. Coupons are deliberately NOT in prisma/seed.ts.
- **Mobile OTA:** ota-publish.yml on push to dev/main when apps/mobile/** changes — fingerprint vs apps/mobile/fingerprints/<channel>.<platform>.fingerprint; JS-only → DRAFT (dev) / CANARY 20% (prod), admin finishes rollout at /admin/ota; native change → warns, needs store build.
- **Native builds:** native-ios.yml / native-android.yml (workflow_dispatch, track testflight|appstore / internal|production). After shipping, bump the fingerprint baseline.
- **Crons:** Vercel crons (vercel.json, /api/cron/*, CRON_SECRET) + GitHub cron workflows (process-reports/rollup-metrics/send-reminders).
- **Secrets:** GitHub — STAGING_DB_URL, PRODUCTION_DB_URL, BLOB_READ_WRITE_TOKEN, mobile signing. Vercel env — see .env.example (DATABASE_URL, AUTH_SECRET, CRON_SECRET, RAZORPAY_*, PHONEPE_*/PHONEPE_DQR_*, BLOB_READ_WRITE_TOKEN, …).
- **Rollback:** web → Vercel instant-rollback (promote previous deploy); OTA → /admin/ota set 0%/promote previous; schema → forward-only.
